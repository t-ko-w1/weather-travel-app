# メールリマインダーの開発・運用

## 動作の概要

- ユーザーが未来のお出かけ記録で明示的に有効にした場合だけジョブを作成します。初期値は無効です。
- 予定日の7日前、日本時間10:00（UTCでは同日01:00）を送信予定時刻にします。日付計算は`Asia/Tokyo`の壁時計時刻からUTCへ変換し、サーバーのローカルタイムゾーンに依存しません。
- 登録時点で送信予定時刻が過ぎている場合は `missed` として記録し、自動送信しません。
- 予定日変更では未送信ジョブを再計算し、通知の無効化や記録削除では未送信ジョブをキャンセルします。送信済みジョブは編集しても再送しません。
- 送信処理はWebサーバーとは別プロセスです。ジョブの一意制約、行ロック、`SKIP LOCKED`、短い処理リースを使います。
- SMTPの成功後、送信履歴のDB確定に失敗すると再起動後に重複送信となる可能性があります。SMTPは一般にexactly-once配信を保証しないため、この残余リスクはなくせません。各試行の `unknown` 状態と安定したMessage-IDで調査しやすくしています。

## 環境変数

実値はGit対象外の `.env` に設定します。Google OAuthの認証情報はメール送信に流用しません。

| 変数 | 用途 | 開発例 |
| --- | --- | --- |
| `MAIL_HOST` | SMTPホスト | `127.0.0.1` |
| `MAIL_PORT` | SMTPポート | `1025` |
| `MAIL_SECURE` | TLS接続 | `false` |
| `MAIL_USER` | SMTPユーザー（任意） | 空欄可 |
| `MAIL_PASSWORD` | SMTPパスワード（任意） | 空欄可 |
| `MAIL_FROM` | 送信元表示 | `Weather Travel <no-reply@example.test>` |

ローカル開発ではMailpitなどのSMTPテスト受信箱を起動し、SMTPを上記の開発値に向けます。Mailpitの管理画面でメール本文を確認できます。実メールサービスへ送信する場合は、その事業者の認証情報・TLS要件・送信制限を確認してください。

## DB準備

`db/migrations/003_reminders.sql` は既存行を削除せず、通知設定列とジョブ・試行履歴テーブルを追加するマイグレーションです。対象が `weather_travel_db` であること、バックアップ、接続先を確認してから運用者が適用してください。この実装作業ではデータベースへ適用していません。

## 手動実行と毎日の実行

一度だけ通知処理を起動します。

```powershell
npm run reminders:run
```

Windowsではタスクスケジューラに毎日10:00（Asia/Tokyo）のタスクを登録し、プログラムを `npm.cmd`、引数を `run reminders:run`、開始場所を `C:\codex` にします。「スケジュールされた時刻にタスクを開始できなかった場合、すぐにタスクを実行する」を有効にすると、復帰後に処理できます。クラウド移行時は同じワンショットコマンドをスケジューラから起動できます。

停止中に予定時刻から24時間以内であれば再起動後に処理します。24時間を超えた未処理通知は `missed` となり、古い通知を突然送信しません。SMTP失敗は最大5試行で、間隔は1分、5分、15分、60分です。

## 動作確認

1. テストDBへマイグレーションを適用し、Googleログインで確認済みメールアドレスのユーザーとしてログインします。
2. 未来日を指定し、通知をオフのまま保存した記録にジョブが作られないことを確認します。
3. 通知をオンにした未来日を保存し、`reminder_jobs.scheduled_at` が予定日の7日前10:00 JSTであることを確認します。
4. MailpitをSMTPに設定し、テスト用の期限到来ジョブに対して `npm run reminders:run` を実行します。画面に保存された宛先以外へ配信しないでください。
5. `reminder_attempts` と `reminder_jobs` の状態、本文の予定日・目的地・活動内容を確認します。

自動テストは実SMTPや実DBを使わず、時計・メール送信・ジョブリポジトリをモックして行います。

## Mailpitへの実メール送信テスト

実SMTPプロトコルをMailpitで確認する場合は、先にMailpitを起動してSMTP `127.0.0.1:1025`、Web UI `http://localhost:8025` を利用できる状態にします。`.env`の`MAIL_HOST`、`MAIL_PORT`、`MAIL_SECURE`がそれぞれ`127.0.0.1`、`1025`、`false`でないとテストコマンドは開始しません。SMTP接続確認とローカル`weather_travel_db`の検証を通過するまでDBにテストデータを追加しません。

```powershell
npm run reminders:mailpit-test
```

このコマンドは一意な`MAILPIT TEST`ラベル付きユーザー・記録・ジョブを追加します。出行日は東京の今日から14日後、送信予定日時はその7日前10:00 JSTです。その日時をテスト用Workerの時計として注入し、**新しく作ったジョブIDだけ**を処理します。グローバルな期限切れジョブ回復は呼ばず、既存ジョブを変更したり送信対象にしたりしません。1回目の送信後にジョブと試行が`sent`、試行数が1であることを確認し、同じWorkerを再実行してclaim 0件・試行数1件のままであることを確認します。

テスト用データは既存行と区別できるようDBに保持します。コマンドの出力に記録ID、ジョブID、marker、件名が表示されます。MailpitのWeb UIでmarkerまたは件名を検索してメールを確認してください。送信先は架空の`example.test`アドレスで、SMTP接続先もlocalhostのMailpitに限定されます。通常の`npm run reminders:run`は全体の期限到来ジョブを処理するため、Mailpit専用のこの確認には使わないでください。
