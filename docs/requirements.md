# お天気・お出かけ記録アプリ 要件定義

## 1. 目的

日々のお出かけについて、日付・場所・活動内容・天気を記録し、あとから一覧や個別画面で確認・編集・削除できるシンプルなWebアプリを提供する。

## 2. 対象範囲

- サーバー：Node.js、Express
- データベース：PostgreSQL
- 画面：HTML、CSS、ブラウザー上で動作するJavaScript
- 天気情報：Open-Meteo Geocoding APIで都市名から座標とタイムゾーンを取得し、選択日が過去なら履歴、今日なら現在、未来なら予報を取得する。天気API呼び出しはNode.jsバックエンドから行う。
- 認証：Google OpenID Connectでログインし、サーバー側セッションを用いて利用者を識別する。記録は所有ユーザーごとに分離する。
- Google OAuth設定値は環境変数から読み込み、秘密値はGitへ追加しない。既存DBへの適用は追加型の移行SQLで行う。

## 3. 利用者と前提

- 主な利用者は自分のお出かけ記録を管理する個人利用者。
- 記録API・天気APIはログインを必須とし、ユーザーごとに記録を分離する。
- 記録日は日付のみで保存する。天気データの今日/過去/未来判定は都市のタイムゾーンを使うが、記録日自体は変換しない。
- 必須入力は日付、都市、目的地。活動内容、備考、天気状況は任意。
- 天気の表現は自由入力とする。例：「晴れ」「曇り」「雨」。

## 4. 機能要件

| ID | 機能 | 要件 |
|---|---|---|
| FR-01 | 記録一覧 | 登録済みの記録を一覧表示する。新しい日付の記録を先に表示する。同じ日付の場合はIDの降順とする。 |
| FR-02 | 記録詳細 | 指定したIDの記録を1件表示する。存在しないIDは「見つからない」と分かる表示にする。 |
| FR-03 | 記録追加 | 日付、都市、目的地、活動内容、備考、天気状況を入力して保存できる。必須項目を検証する。 |
| FR-04 | 記録変更 | 既存記録の項目を編集して保存できる。変更後の内容を確認できる。 |
| FR-05 | 記録削除 | 対象を確認したうえで1件を削除できる。削除後は一覧に戻る。 |
| FR-06 | 入力エラー表示 | 必須項目不足、不正な日付、文字数超過などを利用者に分かる形で表示する。 |
| FR-07 | 天気入力・検索 | 天気状況は手入力でき、未入力でも記録を保存できる。都市と選択日から過去の履歴、今日の現在天気、未来の予報を取得・表示する。天気区分、現在気温または日別最高・最低気温、降水量、対象日、取得日時を区別し、天気文字列をフォームへ反映する。 |
| FR-08 | Googleログイン | Googleアカウントでログインし、初回はGoogleの安定した`sub`を使ってusersへ登録する。 |
| FR-09 | 所有者認可 | ログインユーザーは自分が所有する記録のみ一覧・詳細・変更・削除できる。他ユーザーおよび未割当の記録は参照・変更できない。 |
| FR-10 | ログアウト | ログアウト操作でサーバーセッションを破棄する。 |
| FR-11 | 記録一覧ページネーション | 初期10件、5・10・20件を選択できる。ページ番号と総件数を表示し、前後ページを移動できる。 |
| FR-12 | メール通知設定 | 未来の予定に対して通知を初期オフで設定でき、確認済みログインメールへ予定日の7日前10:00 JSTに通知する。 |
| FR-13 | 通知履歴・再試行 | 通知ジョブと各送信試行をDBに保存し、排他制御のうえ最大5回再試行する。既存記録の変更・削除・通知解除に連動して未送信ジョブを再計算またはキャンセルする。 |

## 5. 画面要件

画面はGoogleログイン画面と記録管理画面を基本とする。記録管理画面には登録・一覧・編集・削除と天気照会をまとめる。未認証では記録管理画面のデータを表示せず、ログイン画面へ案内する。

## 6. 入力・表示ルール

- `date`は`YYYY-MM-DD`形式。
- `city`、`destination`は空白のみを不可とする。
- 前後の空白を除去して保存する。
- 文字数上限はDB定義に合わせ、超過時は保存せずエラーを表示する。
- 利用者入力をHTMLとして解釈しない（画面表示時にエスケープする）。
- 一覧が空の場合は「記録はありません」と表示する。

## 7. 非機能要件

- REST形式のJSON APIを提供する。
- DBアクセスはパラメーター化クエリーを使い、SQLインジェクションを防ぐ。
- ページ付き記録一覧はサーバー側で`LIMIT`/`OFFSET`を使い、ログイン中ユーザー自身のデータだけを取得する。
- 天気APIはバックエンドのみから呼び出し、タイムアウト・外部障害時も記録CRUDを利用できる。
- エラー時に内部スタックトレースやDB情報を画面/API応答に含めない。

## 8. 受け入れ基準

- 記録を追加すると一覧と詳細に反映される。
- 一覧から対象の詳細を開ける。
- 編集内容が保存され、再取得時にも反映されている。
- 削除後は対象IDの取得が404となり、一覧に表示されない。
- 必須項目や入力形式が不正な場合、保存されず理由が示される。
- 天気を入力しない場合と入力した場合の両方で記録できる。
- 過去・今日・未来の日付で適切な天気種別を取得し、取得失敗時も記録CRUDを継続できる。
- 未ログインでは記録・天気APIを利用できず、別ユーザーの記録へアクセスできない。
- 既存の未割当記録はDBに保持され、所有者の確認後に明示的な移行で割り当てられる。
- メール通知は通知設定を有効化した未来予定だけが対象となり、登録時点で通知予定時刻を過ぎている予定は自動送信しない。
