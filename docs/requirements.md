# お天気・お出かけ記録アプリ 要件定義

## 1. 目的

日々のお出かけについて、日付・場所・活動内容・天気を記録し、あとから一覧や個別画面で確認・編集・削除できるシンプルなWebアプリを提供する。

## 2. 対象範囲

- サーバー：Node.js、Express
- データベース：PostgreSQL
- 画面：HTML、CSS、ブラウザー上で動作するJavaScript
- 天気情報：外部天気APIとは接続しない。利用者が入力するか、開発時に仮データを登録する。
- 本段階の成果物は要件・DB・API・テストの設計書であり、アプリケーション実装や既存DBの変更は対象外。

## 3. 利用者と前提

- 主な利用者は自分のお出かけ記録を管理する個人利用者。
- 認証・複数ユーザー管理は初期版の対象外。
- 日時は日付のみを扱い、タイムゾーン変換は行わない。
- 必須入力は日付、都市、目的地。活動内容、備考、天気状況は任意。
- 天気の表現は自由入力とする。例：「晴れ」「曇り」「雨」。

## 4. 機能要件

| ID | 機能 | 要件 |
|---|---|---|
| FR-01 | 記録一覧 | 登録済みの記録を一覧表示する。新しい日付の記録を先に表示する。同じ日付の場合はIDの降順とする。 |
| FR-02 | 記録詳細 | 指定したIDの記録を1件表示する。存在しないIDは「見つからない」と分かる表示にする。 |
| FR-03 | 記録追加 | 日付、都市、目的地、活動内容、備考、天気状況を入力して保存できる。必須項目を検証する。 |
| FR-04 | 記録変更 | 既存記録の項目を編集して保存できる。変更後の内容を確認できる。 |
| FR-05 | 記録削除 | 対象を確認したうえで1件を削除できる。削除後は一覧に戻る。 |
| FR-06 | 入力エラー表示 | 必須項目不足、不正な日付、文字数超過などを利用者に分かる形で表示する。 |
| FR-07 | 天気入力 | 天気状況は手入力でき、未入力でも記録を保存できる。外部API取得は行わない。 |

## 5. 画面要件

初学者向けに画面は次の4種類に絞る。

1. **一覧画面**：記録の要約、詳細・編集・削除へのリンク、新規登録へのリンク。
2. **登録画面**：記録項目の入力フォーム。
3. **詳細画面**：1件の全項目と編集・削除操作。
4. **編集画面**：現在値を初期表示する入力フォーム。

画面遷移はHTMLフォーム送信または`fetch`によるAPI呼び出しで実現できる。初期版では複雑なSPA構成を前提としない。

## 6. 入力・表示ルール

- `date`は`YYYY-MM-DD`形式。
- `city`、`destination`は空白のみを不可とする。
- 前後の空白を除去して保存する。
- 文字数上限はDB定義に合わせ、超過時は保存せずエラーを表示する。
- 利用者入力をHTMLとして解釈しない（画面表示時にエスケープする）。
- 一覧が空の場合は「記録はありません」と表示する。

## 7. 非機能要件

- REST形式のJSON APIを提供する。
- DBアクセスはパラメーター化クエリーを使い、SQLインジェクションを防ぐ。
- 想定規模は個人利用の小規模データとする。ページネーション、検索、認証、画像添付、天気自動取得は初期版の対象外。
- エラー時に内部スタックトレースやDB情報を画面/API応答に含めない。

## 8. 受け入れ基準

- 記録を追加すると一覧と詳細に反映される。
- 一覧から対象の詳細を開ける。
- 編集内容が保存され、再取得時にも反映されている。
- 削除後は対象IDの取得が404となり、一覧に表示されない。
- 必須項目や入力形式が不正な場合、保存されず理由が示される。
- 天気を入力しない場合と入力した場合の両方で記録できる。
